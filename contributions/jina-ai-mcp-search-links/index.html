Jina AI MCP server: search pages that lost their search words

A bug report with its cause and a proposed fix, adopted by Jina AI's founder

Reported 19 July 2026 · fixed 11 August 2026 · code by Jina AI's founder, following my proposal

The software

Jina AI builds search technology for AI systems: services that read web pages, search the web, and find and rank the most relevant text. Elastic, the search-software company listed on the New York Stock Exchange, completed its acquisition of Jina AI in October 2025 and describes it as “a pioneer in open source multimodal and multilingual embeddings, reranker, and small language models” (Elastic press release).

The Jina AI MCP server is Jina AI's official tool that gives AI assistants these services through the Model Context Protocol (MCP), a common standard for connecting AI assistants to tools (its code on GitHub).

How widely it is used. Jina AI runs the server as a hosted service and does not publish usage numbers. Its code repository has 921 stars on GitHub (21 November 2026).

The problem

When an AI assistant asked the server to read a web address containing ?s=, the server removed that part before fetching the page, because it treated it as a session code: a tracking value that is safe to strip. On WordPress websites, ?s= carries the words of a search, so asking for a search-results page returned the site's home page instead.

What I did

I reported the problem on 19 July 2026, explained why it happened, and proposed a narrow fix that keeps ?s= while the server goes on removing real tracking codes (issue #29).

What happened

On 11 August 2026 Jina AI's founder and former chief executive, now Vice President of AI at Elastic, fixed it (commit ec99603, which says “Closes #29”) and replied on the report:

“Confirmed and fixed in ec99603. … Your diagnosis of the cause was exact. Went with the narrow change you proposed … Thanks for the precise report.”

Release. Jina AI runs this server as a hosted service and publishes no version numbers, so there is no release to cite. The reply said the fix would be live on the hosted service after its next update.

Who wrote the code

The code change was written by Jina AI's founder, who chose the narrow fix proposed in my report.
