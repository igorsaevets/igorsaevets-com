Playwright MCP: a file-saving failure on Windows

A bug report and diagnosis that led Microsoft's Playwright team to fix the problem

Reported 16 November 2026 · fixed 18 November 2026 · code by the Playwright team's automated assistant · not yet in a published version

The software

Playwright is free, open-source software from Microsoft that controls a web browser automatically. Developers use it to test websites: it opens pages, clicks, types and checks what appears, the way a person would. Microsoft announced it in January 2020 (Wikipedia).

Playwright MCP is part of the same Microsoft project. It lets AI assistants use a real web browser: open a page, read it, click, fill in forms and save screenshots or PDF files. It works through the Model Context Protocol (MCP), a common standard for connecting AI assistants to tools. GitHub's AI coding assistant, Copilot coding agent, uses it as its built-in web browser (GitHub, 2 July 2025).

How widely it is used

  • Playwright was downloaded 182,298,598 times from npm, the main public registry of JavaScript software, in the week of 14–20 November 2026, and 34.1 million times from PyPI, the Python registry, in the week before 21 November 2026.
  • On GitHub it has 100,713 stars, and 561,996 public repositories depend on it (21 November 2026).
  • Playwright MCP was downloaded 11,330,185 times from npm in the week of 14–20 November 2026 and has 39,961 stars on GitHub.

Download counts include automatic installs by build servers, so they show how much the software is used, not how many people use it. A GitHub star is a bookmark a user gives to a project.

The problem

An AI assistant can ask Playwright MCP to save a screenshot or a PDF under a file name it chooses. On Windows this failed with a “permission denied” error whenever the AI app had started the tool inside C:\Windows\System32, a protected system folder where ordinary programs may not write, and had not told it which project folder to use. Playwright MCP already moved files with automatic names to a safe folder in this situation, but files with a chosen name were not covered, and its check of whether a folder can be written to gave the wrong answer on Windows.

What I did

I ran into the failure while using an AI desktop app on Windows. I reproduced it with a short script, traced both causes to the lines of Playwright's source code responsible, and reported it on 16 November 2026 with the script, the exact error and my test setup (issue #44138).

What happened

  1. 16 November 2026. The same day, the Playwright team passed the report to its automated assistant, which reproduced the problem and opened a fix (pull request #44155). The fix's description restates the diagnosis from my report — “fs.accessSync(W_OK) does not check Windows ACLs”, that is, the standard check does not see Windows file permissions — and ends with “Fixes https://github.com/microsoft/playwright/issues/44138”.
  2. 18 November 2026. Two Playwright maintainers approved the fix, and it was merged into the main code.
  3. Release. As of 28 November 2026 the fix is not yet in a published version: the latest, 0.0.86, was published on 18 November, shortly before the fix was merged.

Who wrote the code

The code of the fix was written by the Playwright team's automated assistant, working from my report, and approved by two maintainers. My part was finding, reproducing and diagnosing the problem and reporting it.
