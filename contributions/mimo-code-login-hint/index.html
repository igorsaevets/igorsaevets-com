MiMo Code: a login hint that pointed to another program

A bug report and a fix of my own, merged by the project, which then fixed the same leftover in two more places

Reported 6 November 2026 · merged 13 November 2026 · my code · not yet in a published version

The software

MiMo Code is an AI coding assistant from Xiaomi, the Chinese electronics company. It runs in a terminal window, where it reads and writes code, runs commands, manages Git (the standard tool for tracking changes to code) and keeps a memory of the project between sessions (its README). Xiaomi released its first version, V0.1, as open-source software in June 2026; it was built from OpenCode, another open-source coding assistant (Fonearena, 12 June 2026).

How widely it is used (21 November 2026)

  • 13,798 stars and 1,478 forks on GitHub (a fork is a copy another developer makes to work on), collected since its repository was created on 10 June 2026.
  • Files attached to its GitHub releases were downloaded 16,893 times.
  • Its npm package was downloaded 12,358 times in the 30 days to 20 November 2026. Xiaomi's instructions recommend a one-line install script from Xiaomi's own website instead, which publishes no count, so these numbers show only part of the use.

The problem

Some tools that MiMo Code connects to ask the user to log in. When that happened, MiMo Code told the user to run opencode mcp auth, a command of OpenCode, the program MiMo Code was built from, instead of its own mimo mcp auth. A user who followed the hint was sent to a different program.

What I did

On 6 November 2026 I reported the problem (issue #2784) and submitted the fix (pull request #2785): the hint now names MiMo Code's own command.

What happened

  1. 13 November 2026. A project maintainer merged my fix into the main code.
  2. Within the next 40 minutes the maintainer merged two more fixes for the same leftover in other parts of the program (pull request #2806 and #2808). The first opens: “Follow-up to #2784 / #2785. That PR fixed the opencode mcp auth hints; this one fixes the remaining places that tell users … to run an opencode command.” #2784 and #2785 are my report and my fix.
  3. Release. As of 21 November 2026 the change is in the main code but not yet in a published version: the latest, v0.1.17, was published on 13 November, before the merge.

Who wrote the code

I wrote this change myself: one line in each of two files. It is in the project's main code under my GitHub account. The two follow-up fixes were written by the maintainer.
