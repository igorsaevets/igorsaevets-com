Open-source contributions

Bug reports and fixes for software made by Microsoft, Xiaomi, Pydantic, Jina AI and the Model Context Protocol project

Open-source software is written in public: anyone can read the code, report a problem or propose a change, and the people who run the project decide what to accept. This page lists problems I found in such software and what the projects did about them. Each entry has a page that explains it in plain English and links to the public record on GitHub, the website where these projects are built.

Only contributions a project acted on are listed: it changed its software after my report, or merged the code I wrote. Each page says plainly who wrote the code and what changed.

How to read these pages

Issue
A public bug report on the project's GitHub page.
Pull request
A proposed change to the code. The project's maintainers review it and either merge it, which means accepting it into the main code, or close it.
Maintainers
The people who run a project and decide which changes are accepted.
Release
A published version that users install. A merged change reaches users with the next release.
Downloads and stars
npm and PyPI, the public registries of JavaScript and Python software, count every download, including automatic ones by build servers, so they show how much software is used, not how many people use it. A GitHub star is a bookmark a user gives to a project.

About this page

Does this page prove anything by itself?

No. It is a summary I wrote. The record is on GitHub: the reports, the code changes, the maintainers' replies and the release notes. That is why every entry links there, with a copy saved by the Internet Archive.

Why are the maintainers not named?

They did not ask to appear on this site. Their names are on the linked GitHub pages.

How were the numbers measured?

From public sources, on the dates shown next to each number: npm's and PyPI's download statistics and GitHub's repository data. Each number links to its source.
