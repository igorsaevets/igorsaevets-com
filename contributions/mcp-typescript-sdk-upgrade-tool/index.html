Model Context Protocol: an upgrade tool that moved license notices

A bug report and diagnosis that led another outside contributor to fix a companion tool of the official MCP TypeScript library; the fix was released

Reported 29 July 2026 · fixed and released 28 September 2026 · code by another outside contributor

The software

The Model Context Protocol (MCP) is an open standard that lets AI assistants connect to the tools and data people work with: files, business software, developer tools. Anthropic introduced it as open-source software on 25 November 2024 (Anthropic). On 9 December 2025 it became one of the founding projects of the Agentic AI Foundation at the Linux Foundation, a non-profit organization for open-source software, together with projects from Block and OpenAI (Linux Foundation).

The TypeScript SDK is the project's official library for building MCP software in TypeScript and JavaScript. It was downloaded 93,842,537 times from npm, the main public registry of JavaScript software, in the week of 14–20 November 2026, and has 13,794 stars on GitHub.

Where this contribution sits. The problem I reported was in a smaller companion tool of that library, its codemod: a program that rewrites a project's code automatically when the project moves from version 1 to version 2 of the library. The codemod was downloaded 444 times in the same week. That is the scale of this contribution; the larger number above describes the library, not this tool.

Download counts include automatic installs by build servers, so they show how much the software is used, not how many people use it.

The problem

Many source files begin with a license notice: a comment at the top that says who owns the code and under which license it may be used. When the codemod updated such a file, it put the rewritten import lines (the lines that load other code) above the notice, so the notice was no longer at the top of the file. Running a code formatter, the clean-up step the upgrade guide recommends, did not move it back.

What I did

I reported the problem on 29 July 2026 with a script that reproduces it step by step (issue #2575). Later the same day I added the name of the function in the codemod's code where the import lines are placed wrongly.

What happened

  1. 30 July 2026. Another outside contributor confirmed the problem — “Both shapes reproduce on main”, meaning both forms of it described in my report occur in the current code — and opened a fix (pull request #2582). Its description says “Fixes #2575” and that it was tested against my reproduction script.
  2. 17 August 2026. A maintainer labeled the report a bug, with priority P2.
  3. 28 September 2026. A maintainer merged the fix, and it was released the same day in version 2.2.0 of the codemod, whose release notes list it.

Who wrote the code

The fix was written by another outside contributor, not by me. My part was finding the problem, showing how to reproduce it, and pointing to where it happens in the code.
