MiMo Code: an automated test that failed at random

A diagnosis and a fix of my own for one of Xiaomi's MiMo Code tests, merged the same day

Reported and fixed 16 November 2026 · my code, merged the same day

The software

MiMo Code is an AI coding assistant from Xiaomi, the Chinese electronics company. It runs in a terminal window, where it reads and writes code, runs commands, manages Git (the standard tool for tracking changes to code) and keeps a memory of the project between sessions (its README). Xiaomi released its first version, V0.1, as open-source software in June 2026; it was built from OpenCode, another open-source coding assistant (Fonearena, 12 June 2026).

How widely it is used is on the other MiMo Code page.

The problem

Software projects run automated tests on every proposed change, to catch mistakes before they reach users. One of MiMo Code's tests failed at random: in the 30 days before my report it failed in 8 of 82 automated test runs, 3 of them on the main code, with no real fault behind it. A test like that wastes developers' time and teaches them to ignore failures. The cause: two tests could be given the same temporary folder when the computer's clock returned the same millisecond for both, so they could interfere with each other's files.

What I did

I counted how often the test failed in the project's records, found the cause, and wrote a demonstration that freezes the clock so the failure happens every time. On 16 November 2026 I reported it (issue #2815) and submitted the fix (pull request #2816): each test now gets its own folder.

What happened

  1. 16 November 2026. A project maintainer re-ran my demonstration. On the main code the test failed (20 passed, 1 failed); with my fix it passed 21 of 21, and 1,050 of 1,050 when repeated 50 times. The maintainer replied: “LGTM, thanks for the clear write-up and repro.” (“LGTM” means “looks good to me”; the “repro” is the demonstration.)
  2. The same day, about six hours after I opened it, the maintainer simplified the fix and merged it into the main code.
  3. The team's own pull request #2817, merged that day, records: “The checkpoint-progress-reconcile flake (#2815) is fixed by #2816, which touches only that test file.” (“Flake” is developers' word for a test that fails at random.)
  4. Release. This change concerns the project's automated tests, not the program people install, so there is no release to wait for.

Who wrote the code

I wrote the fix: each test gets its own session folder. Before merging, the maintainer simplified it, removing steps that had no effect; that change is a second commit in the same pull request. The merged result is in the project's main code under my GitHub account.
